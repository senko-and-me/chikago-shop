# Правила работы агентов

`ORCHESTRATION_PLAN.md` хранит требования, решения, граф задач и статусы. Этот файл хранит рабочий протокол.

## Перед началом

Исполнитель читает только:

1. «Текущий фронт» в плане;
2. строку назначенной задачи;
3. её `CP-*`;
4. явно названные в пакете разделы спецификации и файлы.

Полный план читает координатор. `source/` не сканируется: открыть его может только назначенный art/design-агент, если задача содержит точный список локальных файлов. Глоб `source/**` не считается допустимым read-set.

Русский текст в PowerShell читать с `Get-Content -Encoding UTF8`, чтобы не принять корректный UTF-8 за повреждённую кодировку.

## Definition of Ready

Задача получает `READY`, только если:

- все task/gate-зависимости имеют статус `DONE`/`PASSED`;
- создан контекст-пакет `CP-*`;
- указаны точные read-set и write-set;
- перечислено `Out of scope`;
- есть наблюдаемая приёмка и команды проверки;
- write-set не пересекается с активными задачами.

## Выполнение

- Координатор назначает одного исполнителя и ставит `IN_PROGRESS`.
- Изменять можно только write-set. Выйти за read-set можно лишь для необходимой диагностики; причину указать в handoff. Расширение write-set согласует координатор.
- Несвязанные и пользовательские изменения рабочего дерева сохраняются.
- Каждое изменение поведения сопровождается тестом в той же задаче.
- В `TradeScene.cs` не добавляется новая доменная логика. Извлечение существующей выполняется только когда явно входит в результат и write-set задачи.
- Параллельная работа разрешена только при непересекающихся write-set. Один агент владеет одной `.tscn`, save schema или планом в момент времени.
- Статусы и сам план меняет координатор после handoff.
- `DONE` допустим только после критериев приёмки и проверок.
- Когда все задачи стадии `DONE`, координатор проверяет её gate-критерии, добавляет дату/evidence, переводит ворота `OPEN → PASSED` и создаёт `CP-*` для первого dependency-satisfied фронта следующей стадии.

## Handoff

```text
Task: Sx-yy
Recommended status: REVIEW | BLOCKED
Changed: <paths>
Checks: <command -> PASS/FAIL>
Acceptance: <что подтверждено>
Read-set exception: <нет или причина>
Risks/blocker: <только остаток>
Next: <одно действие>
```
